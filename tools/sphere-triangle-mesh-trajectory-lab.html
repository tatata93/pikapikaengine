DEFINED SEGMENT / STRICT GUARD

両端だけでなく、
定義した経路全体を確かめる。

球中心の線分 p(s) = start + s(end − start)、0 ≤ s ≤ 1 を最大64面へ照会します。全区間のstrict非接触、内部の点貫通witness、証明できない残領域を区別し、全診断を保存します。

sは無次元のparameterです。時刻・速度・重力を進めるWorldや一般CCDの計算ではありません。点witnessは最初の衝突時刻を表さず、跳ね返りや摩擦の応答にも未接続です。

実C++ WebAssemblyを準備中。操作にはHTTP/HTTPS配信とJavaScriptが必要です。

定義経路と、選択auditの返却box

青は経路box、黄は厳密なp(m)を囲むpoint box、赤×は任意のbinary64 anchorです。anchorを厳密なpath点へ置き換えません。

図はXY/XZ/YZへの説明投影です。boxは表示上の線幅を3px拡張します。図の重なりや細さは包含・非接触・描画精度の証明ではありません。表示不能でも数値結果は変更しません。

全parameter領域 [0,1]

青はsafePrefix、緑はclosedな証明葉、橙は未認証current、灰は未照会frontier、赤線は点witness。極小区間はinkだけを最小1pxで示します。正確な両端は下の表を参照してください。

原入力を編集し、実SDKへ照会

SI：位置・半径・幅はm。右手系、Y上。parameter sは無次元。

start/end/radius・全source・全品質/予算設定を編集できます。SDK容量は64面。65面例はhost拒否を表示し、切り詰めません。編集直後に旧結果を消し、再照会を待ちます。

全体判定と、既知work・保守上限

separatedだけが全定義経路のstrict非接触です。not_certifiedは安全でもmissでもありません。safePrefix:nullをs=0の安全へ置き換えません。

結果を読む順序

  1. 全体status/reasonとsnapshot/workExactを確認します。点witnessをTOIや衝撃応答と呼びません。
  2. safePrefix、全証明葉、current、未照会frontierを見て、残領域を省略していないことを確認します。
  3. auditとsourceを切り替え、lastMeshAuditIndexと全候補を確認します。閲覧や投影変更では再照会しません。
  4. 原入力を変更すると旧表示/保存状態が消えます。新しい実query後に完全JSONを保存し、実行した条件を残します。
