# ADR 001 — 最初の縦断実装

日付: 2026-11-03。状態: 採用、制約付き。

C++20標準ライブラリの共通コアをCMakeで作り、Windowsの最初の実GPU経路にはDirectX 12を採用。ブラウザは標準WebGPU/WGSLへ直接接続する。独自のGPU APIを大量に抽象化する前に、両経路で実描画を検証した。

WindowsはWin32/DXGI/D3D12とSDKのD3DCompileを使用。Qtをランタイム依存にしない。OS/GPU API実装を製品へ同梱しない。現状のWindows描画は面ごとの色付け、ブラウザはGGX直接光・環境光近似で、画像一致を主張しない。ブラウザは非対応/初期化失敗/デバイス喪失をUIへ表示し、音声は操作後に開始する。

現地にWebAssemblyコンパイラがなかったため、最初のブラウザ試作は自作ECMAScriptで動作をつないだ。C++とJSが一つのゲームロジックを共有できたとはしない。共通C ABIの衝突/音響/積分の小さいソースを分離し、C++からも実際に使用する。WASMビルド実証を次の優先項目に置く。独立実装の比較テストも維持する。

座標は右手系・Y上、長さm、時間s、質量kg、角度rad。シミュレーション120Hz、描画は前後状態を補間。追いつき上限を超えた時間は記録する。これは通信や異種CPUの完全ビット一致を保証する設計ではない。ロボットの加速/ブースト/上昇はゲーム用制御、軸別の箱衝突は簡易コントローラーであり汎用剛体ではない。

ブラウザの原本JSONはversion1、string安定ID、位置/寸法/Y軸回転/色/boxを持つ。ネイティブは版付きテキスト、53bit以下の数値ID、Quaternion、box/plane/robot、半径を持つ。`engine/portable-scene.mjs`が両者を交換する。元のnativeIdを保持し、ブラウザ由来IDは決定的ハッシュ+メタデータコメントで保存する。ネイティブ編集後もコメントを保持し、色・名前・文字列IDが戻ることを実行検証した。衝突する数値IDやY以外の回転は拒否する。ネイティブ原本の全Quaternion機能をWebへ読み込めるとはしない。

ゲーム進行データはScene原本と分離。共通編集APIにはundo/redoを実装し、シーン変更時には都度現在の障害物リストを参照するため古い箱衝突を残さない。回転障害物、階層、メッシュ頂点編集は未対応。今後の形式変更には移行と互換性試験を要する。

音源発音と伝搬は別API。343m/s・自由音場・点音源・基準1mの仮定でdelay=d/c、振幅min(1,1/d)。ブラウザの音声APIは発振と出力の標準基盤、自前コードが経路値を決める。パンはHRTFではなく、固定経路の試作音を発音時にスケジュールする。移動経路連続更新、ドップラー、反射は未実装。

配信は公開repoのGitHub Pagesで静的配信し、対戦サーバーとは別。開発サーバーは127.0.0.1のみ、秘密ファイル/パストラバーサルを拒否する。課金サービス・契約・フォーラム/メール操作は行わない。

追記: 共通C ABIは標準Ubuntu runnerのclang18.1.3でWASMへ実コンパイルし、Nodeと実ブラウザで実行済み。650Bのバイナリとsource/binaryハッシュを保存し、JSの球衝突・直接音がこれを呼ぶ。C++シーンやゲーム全体のWASM化は未完。camera/source/listener型のtransformも原本と共通形式に追加し、native CLIのaudio-sceneが実際に消費する。
