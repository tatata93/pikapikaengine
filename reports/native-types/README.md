# Typed scene native smoke

This follow-up evidence checks the v1 scene extension for camera, source, and
listener without replacing `reports/native-smoke.*` from the earlier renderer
milestone. It was run on 2026-11-03 JST using the current C++20 Release build,
MSVC 19.51.36247, Windows SDK 10.0.26100, and the hardware DX12 device (not WARP).

`typed.scene` was generated by `pikapika init`. The hidden Windows viewer ran
`--smoke-test --scene typed.scene` for 120 submitted frames, returned exit code 0,
and copied the last color target back from the GPU to `native-smoke.png`. That
image was opened and visually checked. The report confirms three geometry
entities and initial camera position `[0,18,65]`; source and listener records were
not rendered as boxes. Scene creation and direct-path WAV generation from its
source/listener pair also pass the executable integration test in
`tests/portable-scene.test.mjs`.

`native-frames.csv` retains every measured loop interval and CPU duration spent
submitting/presenting/waiting, including startup and stalls. These are not display
presentation statistics or GPU timestamp measurements. The report has p50
16.6783 ms, p95 20.3223 ms, p99 25.4096 ms, maximum 30.4355 ms, and 63 of 120 loop
intervals above 1000/60 ms. GPU time remains unavailable and display 60fps is not
verified. This is a small renderer smoke scene, not representative gameplay
performance and not evidence that the 60fps requirement is met.

The Windows preview uses stored camera position and forward direction (yaw and
pitch), fixed 60-degree vertical field of view, and a 1280 by 720 color/depth
target. It does not display camera roll. Source/listener transforms are authoring
and direct-path input data; this preview does not provide native spatial playback.

Tracked PNG is a lossless conversion of the original BMP GPU readback.
