# 浮力ラボとNative浮遊体の結合

2026-11-03 JST。メッシュ/物理基盤 `3d463d7` の公開成功を確認した後、そのまま次の節目を開発した。

## ブラウザの操作ラボ

`docs/learn/buoyancy.html` は実際の `engine/hydrostatics.mjs` を使う。箱寸法・質量・高さ・Z軸傾きを指定し、濡れた三角形の静水圧積分から排水量/浮力/重心まわりのトルクを計算する。図はXY断面、奥行も3D計算へ反映。これは指定姿勢の瞬時計算で、自動の浮沈・回転やCFDではない。

IABで次を実操作して確認した（ρ=1000kg/m³、g=9.80665m/s²、水面y=0m）。

| 入力 | 画面の実計算結果 |
|---|---|
| 4×2×2m、8000kg、中心y=0m | 排水8m³、浮力/重力78,453.20N、鉛直合力/τzほぼ0 |
| 同じ箱で中心y=+.5m | 排水4m³、浮力39,226.60N、下向き合力−39,226.60N |
| そのまま4000kg | 重力39,226.60N、鉛直合力ほぼ0 |
| 初期値へ戻してZ傾き+20° | τz=−24,730.23N m、傾きを戻す向き |
| .5×6×2m、3000kg、中心y=0m、Z傾き+20° | 排水3m³、浮力/重力29,419.95N、τz=+15,018.82N m、傾きを増す向き |

リセット、入力欄/単位と描画の更新も確認。最終importmap生成後の再読込で初期釣合いを確認。図と値は[釣合い画像](buoyancy-lab-balance.png)、[不安定な形状の図](buoyancy-lab-unstable.png)。本文/SVGはfile://でも読める。ESMによる操作にはHTTP/HTTPSが必要で、その条件と静的な式/既知値をページへ表示する。

`npm run build` / `npm run check` / `npm test` 成功。Node60試験、失敗/skipなし。教材12試験のうち追加3件は、実計算核と実UI moduleを使って質量/沈み位置/roll/乾燥/過重量/無効入力/リセットを検証する。無効入力では古い図と結果を残さない。

## JSとNativeの数値比較

`node scripts/verify-buoyancy.mjs` でNative CLIの `--fixtures` 出力をJSの実計算へ渡した。乾燥/半没/全没箱、水面変更、平行移動、拡大/yaw/roll、CoM偏心、変形箱、部分浸水四面体、非接続shellの12ケース・153数値を比較。最大絶対差5.820766091346741×10⁻¹¹、許容は絶対10⁻⁸+相対10⁻¹¹。[比較記録](buoyancy-parity.json)。これは両言語間の差異を検出するもので、独立した物理的真値の代わりにはしない。解析形状・釣合い・運動の試験を別途用いる。

各入口のES moduleを同じbuild IDで配信する対象に浮力ラボを追加。HTML内importmapは生成物、エンジン側の原本importは通常の相対指定を維持。炎のclassic scriptは従来どおりfile://でも動く。

## Nativeの浮遊体

C++に準備済みの閉メッシュ、静水圧/浮力/CoMトルク、荷重を既存Worldへ加えるAPIを追加。無接触1物体限定の結合は半刻みの姿勢を予測して浮力を再評価し、実刻みへ中点の力/トルクを与える。失敗時は元の状態と荷重を維持する。抵抗/減衰は追加していない。

参照は4×2×4mの箱、ρ=1000kg/m³、g=10m/s²。半没質量16,000kgの釣合い、±0.1m級の上下振動、全没中性浮力の重心偏心による復原を検証。上下振動は既知の調和運動、復原回転は独立したスカラー振り子積分と比較した。2秒後の上下運動の位置/速度合成誤差は刻み1/30,1/60,1/120秒で1.44615019×10⁻⁴、3.59505004×10⁻⁵、8.97489276×10⁻⁶m相当、最初の比4.02261。100秒の上下振動の最大相対エネルギー誤差は120Hzで3.59258×10⁻⁴、240Hzで4.49146×10⁻⁵。全没偏心復原10秒では3.42096×10⁻⁵。完全保存の主張ではない。

初回の4×2×2mの釣合い長時間試験では狭い奥行方向が静水力学的に不安定だった。両方向が安定な4×2×4mへ参照を変更し、元の箱の微小pitchでは傾きを増すトルク、新しい箱では復原するトルクの符号を別試験へ残した。元の不安定性を許容誤差の拡大で隠していない。

最終Native CTest3/3、hydrostatics/coupling20検証群。既存core15+dynamics16も成功。[検証出力](buoyancy-native-tests.txt)、[設定・ソースハッシュ・誤差](buoyancy-native.json)、[静的比較の全入力](buoyancy-fixtures.json)。初期エネルギー0のequilibrium記録の`relative_energy_error`欄は1J正規化で、初期エネルギーに対する比ではない。釣合いは位置/速度の誤差で判断する。heave/rollの同欄は非ゼロの初期エネルギーに対する比。

[全38,400刻みCSV（gzip）](buoyancy-trajectory.csv.gz)は元の9,894,324バイトから数値を変更せず圧縮した。解凍後のバイト一致とSHA256を[manifest](buoyancy-trajectory.manifest.json)で検証。釣合い10秒1200刻み、上下振動100秒を120/240Hzで12000/24000刻み、偏心復原10秒1200刻み。全行を保持する。

[CPU時間の全ケース集計](buoyancy-cpu-profile.json)では、120Hz上下振動のp50=.0078ms、p95=.0095ms、p99=.0265ms、max=5.1058ms、8.333ms超0/12000。240Hzではmax=4.8205ms、4.167ms超2/24000（最大連続1）。描画・音・CSV書込み・実提示を含まず、実行環境の揺らぎもある。単一箱の結果を多数船体や60fps製品の保証へ一般化しない。

球の半径.25mは既存Worldの接触代理データであり、浮力に使う箱と一致する接触形状ではない。この参照は接触0を検査し、一般形状の衝突まで成立したとはしない。水面の変化・流体の運動量反作用・付加質量・造波・粘性・材料損傷・実船の校正は未対応。モデルの定義と研究境界は [BUOYANCY.md](../docs/BUOYANCY.md) を参照。
